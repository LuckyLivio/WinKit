# WinKit 架构与技术决策 (ARCHITECTURE.md)

## 1. 工程结构

工程直接位于仓库根目录（不嵌套次级同名目录），前后端职责清晰分离：

```text
WinKit/
├── docs/                       # 路线图、102 项对照表、设计规范、架构、验证与交接文档
├── src/                        # React + TypeScript 前端界面与纯前端确定性引擎
│   ├── components/             # 侧栏、顶栏、搜索框、退出拦截弹窗等壳层组件
│   ├── i18n/                   # zh-CN / en-US 双语文案字典与类型约束
│   ├── lib/                    # 偏好设置持久化、会话内存状态、Tauri IPC 与任务订阅封装
│   ├── registry/               # 轻量工具注册表（稳定编号、分类、关键词、真实状态）
│   ├── styles/                 # 语义色彩令牌与桌面布局样式
│   └── tools/                  # 真实已实现的工具工作区与测试（D01、D03、I03）
├── src-tauri/                  # Rust 后端与桌面宿主配置
│   ├── capabilities/           # 最小权限声明（仅窗口核心与受控打开/保存对话框）
│   ├── icons/                  # 原创应用图标资源
│   └── src/                    # 文件安全守卫、可取消任务管理、流式 SHA-256、图像装裱导出
├── README.md
└── THIRD_PARTY_NOTICES.md
```

## 2. 关键技术决策

### 2.1 稳定的应用标识与原生窗口宿主

- 应用标识固定为 `com.luckylivio.winkit`，产品名固定为 `WinKit`，安装模式默认 `currentUser`（无需管理员提权即可完成用户态安装与升级）。
- 保留 Windows 原生标题栏（`decorations: true`），完整继承系统窗口拖拽、最大化贴靠布局（Snap Layouts）与快捷键交互。
- 开启 `dragDropEnabled: true`，直接接收桌面原生文件路径拖放事件，而非仅依赖浏览器 `<input type="file">`。

### 2.2 最小权限与集中式文件安全

- 前端不持有任意 `shell` 执行或全盘 `fs` 自由读写权限；仅启用 `dialog:allow-open` 与 `dialog:allow-save`。
- 所有文件读取与导出统一经过 Rust 后端校验：
  - 校验路径非空、不含非法控制字符、目标类型正确，完整兼容中文、空格与非 ASCII 路径。
  - **禁止覆盖原文件**：对输入路径与输出路径执行规范化比对（Windows 下大小写不敏感），若指向同一路径立即拒绝。
  - **防静默覆盖同名文件**：未显式允许覆盖时使用原子排他创建（`create_new(true)` / 临时文件校验），并对只读目录、文件占用、取消操作返回可理解的结构化错误。
  - **隐私最小化**：错误提示与日志绝不拼接或回显用户 JSON 正文、哈希文本内容或图片像素缓冲区。

### 2.3 偏好持久化与会话工作状态分离

- **磁盘持久化**（`localStorage`）：仅存储主题模式（`light`/`dark`/`system`）、界面语言（`zh-CN`/`en-US`）、收藏工具 ID 列表、最近使用工具 ID 与访问时间。
- **会话内存态**：在工具间切换时于内存中保留各工具当前输入与参数，应用关闭即释放，默认绝不将用户输入文本、路径或潜在密钥落盘。

### 2.4 真实流式进度、取消与关闭保护

- 文件哈希等长耗时操作在独立阻塞线程池中以固定大小缓冲区（256 KB）分块流式读取，不将整个大文件读入内存。
- 每个分块检查 `AtomicBool` 取消令牌并推送真实已处理字节数与总字节数，绝不使用定时器伪造进度条；任务取消或报错后严禁残留“成功”状态。
- 当存在运行中任务时，监听窗口关闭请求并弹出确认提示，明确告知关闭将终止当前任务且当前版本不在系统托盘后台继续运行。

### 2.5 首期三项工具的核心正确性保障

- **`D01` JSON 格式化与校验**：实现独立的 RFC 8259 词法与递归下降语法分析器，数字字面量以原始词法切片保存与输出，从根本上杜绝 `JSON.parse` 往返 `Number` 导致超过 `2^53 - 1` 大整数或末尾小数精度被静默篡改；绝不使用 `eval`；语法错误定位到真实 1 基行号与列号。
- **`D03` 哈希工具（SHA-256 子集）**：文本模式严格按原始 UTF-8 字节计算（不暗中 `trim` 空格或换行），文件模式采用 `sha2` 流式读取并支持 `sha256:` 前缀、`shasum` 行格式、冒号/空格分隔及大小写不敏感的 64 位十六进制比对。
- **`I03` 截图美化（基础子集）**：前后端共用同一纯像素框体布局公式（原图始终保持 1:1 原始像素尺寸居中绘制，绝不拉伸模糊原图），在分配内存前强制检查输入/输出尺寸上限，使用 SDF 抗锯齿圆角遮罩（保留源 PNG 透明通道）与可分离盒式近似高斯阴影合成真实高清 PNG。
